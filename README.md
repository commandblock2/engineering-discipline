# engineering-displine
Skill for displine for LLMs. This serves as a experiment of describing personal tastes to LLMs.

LLMs can output defensive code and does not properly keep invariant in the way I want them to, producing unmaintainable code. I believe that is because LLMs don't have a proper taste or understand what means maintainable, but a taste should be describable with natural language, at least, to finally approach what we mean by having a taste.

My stance about LLMs roughly is the same as https://newsletter.powderworks.dev/p/tabs-spaces-hand-tools-and-seat-belts. And due to the quality of LLM produced code and understanding requirement, for some project for me will **NOT** include code written by LLMs, at least at the moment. For others I can't care enough to write myself, LLMs will be used for code creation, but I would still try to at least introduce this set of discipline to set the bars a bit higher
